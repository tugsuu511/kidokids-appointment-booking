# Цаг бүртгэл

- Амжилттай нэвтрэхэд цагийн бүртгэл эхэлнэ. 24 цагийн дотор дахин нэвтрэхэд нээлттэй бүртгэлийг үргэлжлүүлнэ.
- «Гарах» (POST `/api/auth/logout`) үйлдэл тухайн нэвтрэлттэй холбоотой бүртгэлийг хаана. Олон төхөөрөмжөөс нэвтэрсэн бол эхний гаралт нийт бүртгэлийг хаана. Хуучин нэвтрэлт шинэ бүртгэлийг хаахгүй.
- Хөтөч хаах, холболт тасрах нь гарсан цагийг тогтоохгүй. 24 цагаас хэтэрсэн нээлттэй бүртгэлийг «Гаралт бүртгээгүй» гэж харуулж, нийт хугацаанд оруулахгүй. Дараагийн нэвтрэлт шинэ бүртгэл эхлүүлнэ. Систем унтарсан хугацааны гаралтыг таамгаар нөхөхгүй. Харин дахин нэвтрэхээс өмнө «Гарах» дарвал урт хугацааны бүртгэлд ч бодит гарсан цагийг хадгална.
- `/attendance`: админ бүх ажилтны тайланг, менежер/эмч/сувилагч зөвхөн өөрийн тайланг харна. Сервер бүх хүсэлтэд идэвхтэй эрхийг дахин шалгана.
- Админ ажилтан болон он, сар сонгож тухайн сарын эхний өдрөөс сүүлийн өдөр хүртэлх тайланг харна. Анх одоогийн сар сонгогдоно. «Өмнөх сар», «Дараах сар» нь ажилтны сонголтыг хадгалж, тайланг шууд шинэчилнэ. Өмнөх жилийн саруудыг ч сонгож болно. Тайлангийн гарчигт сонгосон ажилтан, сар, хамрах огноог харуулна.
- Огнооны шүүлтүүр Улаанбаатарын цагаар нэвтэрсэн өдөрт хамаарна. Дуусах огноо багтана. Шөнө дамнасан бүтэн хугацааг нэвтэрсэн өдөрт тооцно. Нийт хугацаа зөвхөн дууссан бүртгэлүүдийн нийлбэр; завсарлага, цалингийн цагийн тооцоо биш.
- Орсон, гарсан цагийн дэлгэрэнгүйг Даваа–Ням гарагтай сарын календарьт харуулна. Өдрийн нүдэнд эхний хоёр бүртгэл, өдрийн нийт хугацаа харагдах ба өдрийг дарахад бүх бүртгэл дэлгэрнэ. Шөнө дамнасан гаралтад дараагийн өдрийн тэмдэглэгээ харагдана. Бүртгэлгүй өдрийг тасалсан гэж тооцохгүй.
- Календарь харагдаж буй сарын бүх бүртгэлийг ачаална (50 мөрөөр хязгаарлахгүй). Ажилтан олон сарын хугацаа сонговол календарийн сумаар тухайн хугацаан дотор сар солих боломжтой. Нэгтгэл бүх сонгосон хугацааг хамарна. Огнооны шүүлтүүрийн дээд хэмжээ 366 хоног хэвээр.
- Өмнө нэвтэрсэн хэрэглэгчид гараад дахин нэвтэрч шинэ бүртгэл эхлүүлнэ. Өнгөрсөн орсон/гарсан цагийг нөхөж үүсгэхгүй.
- Цагийн түүхтэй ажилтныг устгахгүй; нэвтрэх эрхийг хааж түүхийг хадгална.

## Өгөгдлийн сан

`20261006000000_add_attendance` migration-ийг серверийн шинэ кодоос өмнө ажиллуулна:

```sh
npx prisma migrate deploy
npm run build
```

Migration нь `Attendance` хүснэгт, хайлтын индекс, нэг хэрэглэгчид нэг нээлттэй бүртгэл байх partial unique index, цагийн дарааллын check constraint нэмнэ. `DIRECT_URL` нь migration-д зориулсан шууд холболт байна. Prisma 6-д partial index болон check constraint-ийг migration SQL-д хадгалдаг тул `db push` нь энэ migration-ийг орлохгүй.

## Шалгалт

```sh
npm test
npm run lint
npm run build
```

Бодит API тестийг зөвхөн тусгаарласан, migration хийгдсэн тестийн сан болон тэр санг ашиглах локал сервер дээр ажиллуулна:

```sh
# ATTENDANCE_TEST_DATABASE_URL: тестийн сангийн холболт
# ATTENDANCE_TEST_DATABASE_HOST: тэр сангийн hostname-ийн давхар баталгаажуулалт
# ATTENDANCE_TEST_BASE_URL: локал сервер, анхдагч http://localhost:3101
npx tsx tests/attendance-api.integration.mts
```
